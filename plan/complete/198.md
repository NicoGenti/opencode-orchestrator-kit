## Goal

Implement issue #198 (Option C — adaptive hybrid) so every request is intake-checked before routing: ambiguous/underspecified requests are restated and confirmed by the user, clear requests are triaged to the appropriate path by documented categorical criteria, and all of this is configured through `workflow.mode` with optional append-only triage telemetry.

## Success Criteria

1. Ambiguous/underspecified requests produce a restated spec and get explicit user confirmation before any delegation; well-formed requests add zero round-trips.
2. The user always sees and confirms the restated spec — no silent rewriting.
3. The skip/lite path is driven by documented categorical criteria (≤1 file, no plan needed, no security sensitivity, no cross-module impact) pinned by tests.
4. Triage telemetry is opt-in, append-only, documented, off by default, and the gate behaves identically when telemetry is disabled.
5. `workflow.mode` (`auto|full|lite`) is documented; `auto` preserves current routing for clear requests.
6. `agents/orchestrator.md` stays within its W1 cap; heavy logic lives in an on-demand skill; `bun test` passes; `plugin/assets` mirrors regenerate with `bun run sync-assets`.
7. `orchestrator-quick` is unchanged except for explicit hand-back/routing wording if needed.
8. README/docs describe the intake step; the comprehension-gate semantics and NONE/LIGHT/DEEP taxonomy are reused, not replaced.

## Notes / Edge Cases

1. **Restatement trigger**: reuse the existing clarifying-questions condition (`agents/orchestrator.md:265`) — missing goal, scope, files, or constraints — replacing that sentence with the restatement protocol so well-formed requests route unchanged.
2. **Skill vs prompt delta**: heavy logic moves to `skills/workflow-intake/SKILL.md`; `agents/orchestrator.md` and `agents/orchestrator-quick.md` keep only thin pointer sections, because the W1 caps leave only +49 and +23 characters of headroom.

4. **Config home**: a new `templates/workflow.config.json` holds `workflow.mode` (`auto` default) and the telemetry opt-in, avoiding changes to the pinned `templates/comprehension.config.json` schema and the `plugin/src/comprehension.ts` loader.
5. **Restated-spec logging**: the restated spec itself is not persisted; only the optional opt-in telemetry row is written, keeping `.context/` lean and respecting the privacy invariant.
