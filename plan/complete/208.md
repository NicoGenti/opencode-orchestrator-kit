## Goal

Add deterministic, opt-in TOON encoding support to the kit's native `plan_board` tool output, gated by a reproducible benchmark in the evals repository; keep JSON as the default and preserve Python/TypeScript parity.

## Success Criteria

- P1 produces a committed report in `opencode-orchestrator-kit-evals/reports/` showing JSON-vs-TOON token reduction for at least two payload shapes, using the deterministic `ceil(chars/4)` heuristic (`docs/CONFIGURATION.md:451`) and optional real-tokenizer validation.
- P1 proves 100% round-trip accuracy (`encode(payload)` → `decode()` → deep-equal) for every shape.
- GATE is recorded explicitly: integration proceeds only if the real `check` payload reduction is ≥10%; otherwise P2 is omitted and only P3 docs are delivered.
- If P2 runs: `plugin/package.json` declares `@toon-format/toon` as a runtime dependency, the tool layer branches on `toon.enabled`, and `runPlanBoard` stays JSON-native so `tests/plan-board-parity.test.ts:268-270` remains green.
- If P2 runs: `tests/plugin-plan-board-tool.test.ts:147,311,322` plus new TOON-branch tests pass, and no agent prompt claims an unconditional skill load.
- P3 updates `docs/CONFIGURATION.md`, `docs/BENCHMARK-TOKEN-USAGE.md`, `README.md:146-189` and `README.md:191-201`, runs `bun run sync-assets`, and keeps `bun run sync-assets --check` green.
- All changes respect `CONTRIBUTING.md` (no secrets, no destructive git actions, no hand-edited `plugin/assets/`).

## Notes / Edge Cases

- **SDK API not yet verified.** The first P1 step must smoke-test `@toon-format/toon` (function names, options, sync vs async) before the benchmark relies on it. Do not assume `encode`/`decode` names.
- **GATE is a user checkpoint.** The plan explicitly stops after P1 for a go/no-go decision; do not begin P2 until the ≥10% threshold is met and recorded.
- **Windows CRLF.** The kit sources use CRLF in the working tree; run `bun run format:check` and `bun run sync-assets --check` rather than relying on local git-blob appearance. ~25 local test failures are known; CI is the truth.
- **`plugin/package.json` currently has zero runtime deps.** Adding `@toon-format/toon` is the first real dependency; keep `bun.lock` in sync and ensure `prepack` still runs cleanly.
- **Agent prompt budget.** Prefer minimal prose changes. If `agents/orchestrator.md` must change (e.g., "RAW JSON" → "RAW payload"), include `tests/comprehension-config.test.ts:384-502` and `tests/workflow-hardening.test.ts` prompt-budget table in the test target set, and update the budget table in the same commit.
- **Offline/dry-run.** The benchmark must not call models or require network at run-time; it only measures serialized bytes.
- **Rejected alternatives:**
  - **JSONL sink** — rejected: would introduce a second output surface, break the existing tool-result contract, and complicate parity testing for no proven gain.
  - **Vendored TOON skill** — rejected: user decision (#208 scoping) mandates `@toon-format/toon` as a real dependency in `plugin/package.json` and evals devDependencies.
  - **V1 Python CLI (`scripts/plan-board.py`)** — rejected: user decision keeps V1 JSON-only; the parity surface is the V2 native tool only.
  - **TOON for prose / agent prompts** — rejected: issue #205 design review explicitly excluded prose/slice encoding; #208 applies only to the structured `plan_board` payload.
