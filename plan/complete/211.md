## Notes / Edge Cases

- The guard insertions run on the dry-run path as well as the write path: place them before the `if not dry_run:` block so a `--dry-run` that would escape the root still reports `path-traversal`.
- `_is_traversal` on raw argv (`:415-419`) already rejects strings containing `..` segments, so `--root ../../evil` never reaches the sinks; the new guards harden against the case where the column directory itself resolves outside root (e.g., a symlink).
- `--to ../../evil` and `--column ../../evil` will continue to return `bad-column`, not `path-traversal`, because the `COLUMNS` membership check runs first. The regression tests must assert `bad-column` plus the absence of an outside-directory creation, not a `path-traversal` code.
- Windows path handling: `_is_traversal` splits both `/` and `\`; the new guards rely on `_outside`/`_resolves_within`, which use `Path.resolve()`, so symlink/normalization handling stays in one place.
- Snyk caveat: the alert is expected to close after the guard reaches the default branch and Snyk re-scans, but the custom Snyk validator is not modeled here. If the re-scan still flags the line, escalation to the user for a Snyk ignore/suppression policy is a follow-up decision, not an in-scope code change.
- No board-file mutations are part of this plan; any `plan_board new/move` operations on the real board are owned by `plan-writer` and require user approval per DR-7.
