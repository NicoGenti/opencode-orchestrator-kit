## Goal

Ship issue #151's two deterministic, offline, LLM-free validation gates — `scripts/context-budget.ts` (per-role input/output context budget) and `scripts/evidence-check.ts` (repository-evidence claim checking) — with pinned JSON schemas, unit tests, role-default configuration, and minimal orchestrator/docs integration, on branch `feat/issue-151-deterministic-gates` with one commit per phase.

## Success Criteria

Mapped one-to-one to the seven acceptance checkboxes of issue #151:

- **SC1 (AC1 — context-budget validates input and output context by agent role)**: `scripts/context-budget.ts` validates a JSON manifest (`role`, `mode: "input"|"output"`, `spec`, `files[]`, optional `output`) against role limits — `explorer` max 8 files / 300 extracted lines / no file over 400 lines; `planner` max 2 context files / 1 phase per delegation; `developer-fixer` max 5 modified files / 1 phase; `code-reviewer` diff-only scope — and emits exactly the report schema of the issue: `{role, verdict, input_tokens_estimate, output_tokens_estimate, file_count, oversized_files: [{path, lines, reason}], blocking_issues}`; roles without pinned limits fall back to the `default` entry; all limits are overridable via config (SC7).
- **SC2 (AC2 — evidence-check validates claims against repository files and symbols)**: `scripts/evidence-check.ts` accepts a claims manifest (`claim`, optional `evidence: "path:line"`, `marker`, `counterMarker`, `securitySensitive`) or a markdown document (`--doc`) whose `path:line` citations are scanned mechanically; every cited file/line is resolved on disk and every marker is matched literally (marker-only — no semantics, no fuzzy matching, no LLM); each claim is classified `verified` / `unverified` / `contradicted` per the locked rules in Phase 3.
- **SC3 (AC3 — deterministic JSON)**: both scripts emit a single JSON object (indent 2) to stdout; the field sets and orders are pinned exhaustively in `scripts/lib/check-common.ts` (the `tests/contract-fields.ts` precedent) and asserted by tests; identical input produces byte-identical output (test-pinned); exit code 0 on `verdict: "pass"`, 1 on `verdict: "fail"` and on usage/IO errors.
- **SC4 (AC4 — no network, no LLM)**: both scripts and the shared lib use only `node:fs` reads and string operations; a static test pins that none of the three files imports `node:http`/`node:https`/`node:child_process` or calls `fetch`; `bun.lock` and both `package.json` dependency blocks are byte-unchanged (zero new dependencies).
